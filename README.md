# Party Hub：多人派對遊戲框架（架構設計）

以一台電腦當主機、接上電視顯示大家共用的畫面，其他人用手機瀏覽器掃 QR code 加入，各自看到**只有自己（或自己陣營）看得到**的資訊。適合海龜湯、狼人殺、簡單桌遊等派對遊戲。

> 本 repo 記錄框架的架構與設計決策。房間系統、即時同步、加入與斷線重連已實作並測試；具體遊戲規則之後再疊加。

技術：Node.js、Express、Socket.IO、QR code

---

## 架構

```
          ┌──────────── 電視／電腦（主機頁 /host）────────────┐
          │ 建立房間、顯示房間代碼與 QR code、推送畫面狀態       │
          └───────────────────────┬────────────────────────────┘
                                  │ Socket.IO
                    ┌─────────────▼──────────────┐
                    │  伺服器（Express＋Socket.IO）│
                    │  房間狀態存在記憶體          │
                    └──────┬─────────┬──────────┘
                           │         │
              ┌────────────▼┐   ┌────▼────────┐
              │ 玩家手機 A   │   │ 玩家手機 B   │  … 最多 N 人
              │ /player     │   │ /player     │
              └─────────────┘   └─────────────┘
```

### 兩種狀態

| 狀態 | 誰看得到 | 例子 |
|---|---|---|
| **共用狀態** | 房內所有人 | 題目、計時、問答紀錄 |
| **私人狀態** | 只有指定玩家（或指定陣營） | 手牌、身分、隊伍筆記 |

主機是唯一能改狀態的角色；玩家只能送「動作」給主機，由主機依遊戲規則決定結果。這樣規則只寫在一個地方，玩家改不了別人的資料。

## 設計決策

### 1. 斷線重連：用 token 認人，不靠連線本身

手機很常斷線：螢幕關掉、切換 App、網路不穩。如果用 WebSocket 連線來認人，一斷線就變成新玩家。

- **主機**：建立房間時拿到 `hostToken`，存在瀏覽器 localStorage。整頁重新整理（例如電視當機重開）時，帶著它就能拿回同一個房間和狀態。
- **玩家**：加入時拿到 `playerId`，依房間代碼存在 localStorage。手機睡眠、切 App、重新整理後，會自動帶著 `playerId` 重連，拿回原本的名字與私人狀態。
- **房間保留**：主機斷線後房間保留 10 分鐘等主機回來，超過才清除。

### 2. 房間存在記憶體，不用資料庫

一場派對用完就結束，不需要永久保存。存在記憶體簡單又快；代價是伺服器重開房間會清空，這對派對情境可以接受。

### 3. 跨網路加入：網址可替換

同一個 WiFi 用區網網址即可。不同網路（例如用行動網路）時，用 Cloudflare Tunnel 這類工具開一個對外網址，貼進主機頁的「加入網址」欄位，QR code 就會跟著更新。沒有寫死任何廠商，換成 ngrok 或自己的伺服器也行。

### 4. 框架與遊戲分離

房間、連線、重連、QR code 是底層，不隨遊戲改變；每個遊戲只要：
1. 在主機端監聽玩家的動作，跑該遊戲的規則；
2. 用共用狀態放所有人都看得到的資訊；
3. 用私人狀態放每人或每陣營專屬的資訊；
4. 替換主機頁與玩家頁的畫面元件。

## 事件協定（Socket.IO）

**主機 → 伺服器**

| 事件 | 用途 |
|---|---|
| `host:create` | 建立新房間，取得 `roomCode`、`hostToken` |
| `host:rejoin` | 用 `roomCode` ＋ `hostToken` 拿回房間 |
| `host:setSharedState` | 更新共用狀態，廣播給房內所有玩家 |
| `host:setPrivateState` | 更新單一玩家的私人狀態，只有該玩家收到 |
| `host:broadcastPrivateState` | 一次更新多位玩家的私人狀態，例如同陣營共用筆記 |
| `host:removePlayer` | 把玩家踢出房間 |

**玩家 → 伺服器**

| 事件 | 用途 |
|---|---|
| `player:join` | 用房間代碼加入；帶上先前的 `playerId` 即可重連 |
| `player:action` | 送自訂動作給主機，例如發問、出牌、投票 |

**伺服器 → 主機／玩家**

| 事件 | 收件者 | 用途 |
|---|---|---|
| `players:update` | 主機 | 玩家名單與連線狀態 |
| `player:action` | 主機 | 玩家送出的動作 |
| `sharedState:update` | 玩家 | 共用狀態變化 |
| `privateState:update` | 玩家 | 自己的私人狀態變化 |
| `room:closed`、`host:disconnected` | 玩家 | 房間異常通知 |

---

## 範例：海龜湯怎麼接上框架

1. 玩家在手機上送 `player:action`：`{ action: "ask", payload: "他是自殺嗎？" }`
2. 主機畫面顯示問題，主持人按「是／否／無關」
3. 主機用 `host:setSharedState` 把問答紀錄推給所有人
4. 湯底只放在主持人的私人狀態，其他玩家拿不到
